# Owl Sudoku 基础版设计

日期：2026-10-17
状态：待评审

## 1. 目标

在现有的 OpenSiv3D 0.6.16 + CMake 模板工程中实现一个可直接游玩的数独游戏：

1. 启动时选择难度：简单、中等、困难、大师。
2. 每个难度随机生成一道**有唯一解**的关卡。
3. 鼠标点选格子，键盘填入数字，全部填对后判定通关。

界面使用简体中文。项目继续沿用现有构建方式（MSVC、静态 CRT、Ninja Multi-Config、GoogleTest）。

## 2. 范围

### 2.1 目标

- 9×9 标准数独。
- 四个难度通过给定数字（线索）数量区分。
- 随机生成完整解，再随机挖空并保证唯一解。
- 可玩的鼠标/键盘交互。
- 填入的数字与同行、同列或同宫已出现的数字冲突时，立即以红色显示。
- 通关后显示完成提示，可再来一局或返回难度选择。
- 核心出题/求解逻辑与界面分离，并由 GoogleTest 覆盖。

### 2.2 非目标（基础版不做）

- 候选数/笔记模式。
- 计时、排行榜、存档。
- 提示、自动检查、撤销/重做。
- 音效、动画演出、主题切换。
- 按人类解题技巧划分的严格难度评估（基础版用线索数量作为难度代理）。

## 3. 用户流程

```text
启动
  → 难度选择界面（简单 / 中等 / 困难 / 大师）
  → 点击难度：同步生成关卡
  → 游戏界面
      ├─ 鼠标点格子、键盘填数
      ├─ 点击“新游戏”：回到难度选择（当前进度直接丢弃，不弹确认框）
      └─ 全部填对：显示完成遮罩
            ├─ “再来一局”：同难度重新随机生成
            └─ “返回难度选择”：回到难度选择界面
```

## 4. 难度设定

用线索数量（题目中预先给出的数字个数）作为难度划分：

| 难度 | 目标线索数 | 可接受上限 |
| --- | --- | --- |
| 简单 | 40 | 46 |
| 中等 | 34 | 40 |
| 困难 | 30 | 36 |
| 大师 | 26 | 32 |

生成规则：

- 随机挖空直到达到目标线索数，或所有格子都尝试过一遍。
- 若最终线索数超过该难度的“可接受上限”，重新生成；最多尝试 4 次。
- 若 4 次都超限，接受线索数最少的一次，保证流程不会卡死。
- 线索数量是基础版的难度代理；不保证“大师”一定需要高级解题技巧。

## 5. 核心模块

新代码放在 `owl_sudoku` 命名空间，不依赖 Siv3D，便于单元测试。

### 5.1 文件

- `include/owl_sudoku/sudoku.h`
- `src/sudoku.cc`
- `tests/sudoku_test.cc`

### 5.2 数据结构与 API

```cpp
namespace owl_sudoku
{
    constexpr int BoardSize = 9;
    constexpr int BoxSize = 3;

    // 每个元素为 0..9，0 表示空格。
    using Grid = std::array<std::array<int, BoardSize>, BoardSize>;

    struct Cell
    {
        int row = 0;
        int column = 0;
    };

    // 把棋盘左上角为原点的坐标映射到格子；越界返回 std::nullopt。
    std::optional<Cell> cellAt(double localX, double localY, double cellSize);

    // 按行/列增量移动格子，并限制在棋盘内。
    Cell moveCell(Cell cell, int rowDelta, int columnDelta);

    enum class Difficulty
    {
        Easy,
        Medium,
        Hard,
        Master,
    };

    struct Puzzle
    {
        Grid givens{};    // 题目；0 表示空格
        Grid solution{};  // 完整解
    };

    // 使用调用方提供的随机数引擎，便于测试复现。
    Puzzle generate(Difficulty difficulty, std::mt19937& rng);

    // 便捷重载：用 std::random_device 播种。
    Puzzle generate(Difficulty difficulty);

    // 计数解的个数，达到 limit 后提前返回（用于唯一解检查）。
    int countSolutions(const Grid& grid, int limit = 2);

    // 是否为一个合法的完整解（每行/列/宫恰含 1..9）。
    bool isValidSolution(const Grid& grid);

    // 是否已填满且合法。
    bool isComplete(const Grid& grid);

    // 指定格子的数字是否与同行、同列或同宫的其他数字重复。
    bool hasConflict(const Grid& grid, int row, int column);
}
```

### 5.3 完整解生成

使用“模式网格 + 随机变换”的方式快速生成完整解：

1. 基础模式：`value(r, c) = (r * 3 + r / 3 + c) % 9 + 1`。
2. 对数字 1..9 做随机置换。
3. 随机打乱三个行带（band）的顺序，再打乱每个行带内部三行的顺序。
4. 对列做同样的“列堆（stack）+ 堆内列”打乱。
5. 得到 `Puzzle::solution`。

这样生成的完整解一定合法，且随机性足够基础版使用。

### 5.4 挖空与唯一解

1. 把 81 个位置随机打乱。
2. 从完整解复制出 `givens`。
3. 依次尝试清空每个位置：
   - 临时清空；
   - 调用 `countSolutions(givens, 2)`；
   - 若解不唯一（返回值 >= 2），恢复该位置；
   - 若唯一，保留清空。
4. 达到目标线索数后停止。
5. 按第 4 节的规则处理未达目标或超出上限的情况。

### 5.5 求解/计数

使用位掩码 + 回溯：

- 维护每行、每列、每宫已使用数字的掩码。
- 每步选择候选数最少的空格（MRV）展开，提高唯一性检查速度。
- 每放置一个数字，计数 +1；达到 `limit` 立即返回。
- 非法输入（重复数字）直接返回 0。

性能目标：任意难度单次生成在普通桌面 CPU 上应低于约 200 ms；界面同步生成即可，不需要加载动画。

## 6. 界面设计

### 6.1 窗口与布局

- 窗口标题：`Owl Sudoku`。
- 窗口尺寸：960×800（启动时 `Window::Resize`）。
- 背景：深蓝灰 `ColorF{0.10, 0.12, 0.16}`。
- 中文文本使用 `Typeface::CJK_Regular_SC` 的位图字体；数字使用 `Typeface::Bold`。
- 标题可使用 `Mplus_Black`，并为 🦉 添加 `Typeface::ColorEmoji` 回退字体。

### 6.2 难度选择界面

- 顶部：🦉 图标、标题 `Owl Sudoku`、副标题“基础版”。
- 中部纵排四个按钮：`简单`、`中等`、`困难`、`大师`。
- 按钮尺寸约 260×64，间距 20，居中。
- 悬停时按钮变亮；点击后生成对应难度关卡并进入游戏界面。

### 6.3 游戏界面

- 顶部栏：
  - 左侧显示当前难度，例如“难度：中等”。
  - 右侧是“新游戏”按钮（约 120×44）。
- 棋盘：
  - 9×9，格边长 60，棋盘总尺寸 540×540。
  - 水平居中，顶部约 y=130。
  - 细线 1px 分隔普通格子，3px 粗线分隔 3×3 宫，外框 3px。
- 底部提示文字：`1-9 填数 · Backspace 清除 · 方向键移动`。

### 6.4 格子状态与配色

| 状态 | 文字颜色 | 背景 |
| --- | --- | --- |
| 题目给定 | 深灰蓝 | 白色 |
| 玩家填入且无冲突 | 蓝色 | 白色 |
| 玩家填入且与已出现数字冲突 | 红色 | 浅红 |
| 选中格 | 按上述文字规则 | 浅蓝高亮 |

- 选中格额外绘制高亮边框。
- 点击题目给定的格子也可以选中，但键盘输入不会改变它。
- 不显示“与选中格同数字”的额外高亮，保持基础版简单。

### 6.5 输入

- 鼠标左键点击格子：选中。
- 数字键 `1`–`9`（主键盘和小键盘）：写入选中格；给定格忽略。
- `Backspace` / `Delete`：清空选中格；给定格忽略。
- 方向键：在棋盘内移动选中格，到边界停止。
- 点击“新游戏”：返回难度选择界面。
- 通关遮罩出现后，棋盘输入全部禁用。

### 6.6 错误标记

- 玩家填入的数字与同行、同列或同宫已出现的数字重复时，判定为冲突并立即标红。
- 不直接与 `Puzzle::solution` 比较；暂时错误但暂无冲突的数字保持正常颜色（蓝色）。
- 冲突数字保留在格中，直到玩家修改或清除；不自动清除、不禁止输入。
- 题目给定格始终不标红；通关判定仍然要求玩家棋盘与唯一解完全一致。

### 6.7 通关

- 每次成功填数或清空后检查：81 格全部非空，且与 `Puzzle::solution` 完全一致。
- 通关后绘制半透明深色遮罩，中央面板显示：
  - 标题“完成！”；
  - 按钮“再来一局”（同难度新关卡）；
  - 按钮“返回难度选择”。
- 不做计时，因此不显示用时。

### 6.8 实现方式

- 不使用 `SimpleGUI`（其内置字体不保证中文显示）。
- 在 `src/Main.cpp` 中实现一个小型按钮辅助函数：绘制圆角矩形、处理悬停与点击。
- 界面状态用简单的枚举区分：`Menu` / `Playing` / `Cleared`（`Cleared` 也可用布尔值叠加在 `Playing` 上）。
- 所有字体、颜色常量在 `Main()` 内一次性创建。

## 7. 构建集成

- 把 `src/sudoku.cc` 加入 `siv3d_template_core`。
- 把 `tests/sudoku_test.cc` 加入 `siv3d_template_tests`。
- 重写 `src/Main.cpp`。
- 构建目标名称保持 `Siv3D_Template` 不变，避免改动 `.vscode` 配置、preset 与输出目录；用户可见的窗口标题为 `Owl Sudoku`。
- 可选：在 `README.md` 增加一节简要说明玩法与难度。属于构建者的 discretionary 改动。

## 8. 测试计划

使用 GoogleTest：

1. 已知完整解：`isValidSolution` 返回 true；`isComplete` 返回 true。
2. 含重复数字的网格：`countSolutions` 返回 0；`isValidSolution` 返回 false。
3. 空棋盘：`countSolutions(grid, 2)` 返回 2（达到 limit 提前返回）。
4. 已知唯一解题目：`countSolutions(grid, 2)` 返回 1。
5. 对四个难度、固定随机种子生成：
   - `solution` 合法；
   - `givens` 非零位置与 `solution` 一致，空位为 0；
   - `countSolutions(givens, 2) == 1`；
   - 线索数量在目标值到可接受上限之间。
6. 相同种子生成相同题目，不同种子（通常）生成不同题目。
7. 通关判定：把 `player` 设为 `solution` 后 `isComplete` 为 true；任意改错一格后为 false。
8. 冲突判定：同行、同列、同宫的重复数字返回 true；与解不同但无重复的数字返回 false。
9. 选择几何：屏幕坐标到行列的映射正确（非对角线格子不发生行列互换）；方向键按行列移动并在边界停止。

生成类测试对四个难度各跑一次即可，避免测试过慢；如需稳定性，可使用多个固定种子。

## 9. 验证方式

1. `tools\cmake-msvc.cmd --build --preset debug`（或现有的 VS Code 构建任务）编译通过。
2. `ctest --preset test-debug` 全部通过。
3. 启动 `App/Siv3D_Template(debug).exe`，人工验证：
   - 四个难度按钮都能生成关卡；
   - 鼠标选中、键盘填数、退格清除有效；
   - 与已出现数字冲突的填入数字显示红色，无冲突的暂时错误数字保持蓝色；
   - 完成后出现遮罩并可再来一局/返回菜单。
4. Release 构建同样编译通过，测试通过。
